# 益米点读笔 · 产品理论定稿

> 状态：**想法与理论冻结版 v0.1**（2026）· 含安全/硬件/商业三专题摘要  
> 用途：后续写代码、做硬件、谈社区时的**唯一共识源**。实现细节可变，本页原则不轻易改。  
> 仓库：`yimi-pen` · 品牌：益米 / Yimi Pen · 协议：Apache-2.0（代码）

---

## 0. 一句话

**益米是开源的「万物可点」底座：用玩具感点读体验 + 家庭/社区自创内容 + 亲情音色，让身边的东西和自制绘本都会说话；不靠大厂锁区书库，不冒充米家官方，不做应试教辅笔。**

---

## 1. 我们是什么 / 不是什么

| 我们是 | 我们不是 |
|--------|----------|
| 幼儿向、玩具感发声体验（可参考小鸡球球/宝贝 JoJo 的「好玩」） | 讯飞类学段教辅笔（课文、搜题、口语考级） |
| 开放格式 + 开源引擎 + 社区/DIY 内容 | 封闭 IP 书库兼容机 / 盗版点读包渠道 |
| 可选智能家居桥接（米家**友好**） | 小米/米家官方产品或生态链认证配件 |
| 亲情音色（打字/AI 用爸妈声朗读） | 声纹门禁、身份核验登录 |
| 创作工具（贴纸、拍照成书） | 「偷大厂资源」的技术项目 |

## 2. 问题与机会

### 2.1 行业结构

- 传统点读：硬件 + **封闭内容**，资源被厂商锁死。  
- GitHub 上几乎没有完整的「幼儿点读 + 开放包 + DIY」开源底座。  
- 家长真实需求里，很大一块是**陪伴与好玩**，不是刷题。

### 2.2 益米选择的切口

不和巨头比「谁家书多、谁家题全」，而比：

1. **内容能否自己长出来**（DIY + 公版 + 合规社区包）  
2. **现实世界能否被点亮**（贴纸贴在香蕉上也会说话）  
3. **声音是否有温度**（家里人的音色，而不是统一机械音）  
4. **规则是否干净**（法律与品牌活得下去）

## 3. 核心命题（护城河）

```
开放生态  +  实体/图书双 DIY  +  亲情音色  +  可选 IoT/AI
```

刻意**不做**的命题：

```
兼容/解密商业点读包  ·  冒充官方米家  ·  应试工具第一
```

**社区规则第一条（理论硬约束）：**  
禁止传播任何受版权保护的商业点读包（破解、镜像、未授权录制分发）。

合法「资源广」只来自：

- 公版 / 公共领域（标注来源）  
- 用户与作者自制  
- 权利人授权  
- **双 DIY 生成物**（家庭为主，公开须合规）

## 4. 体验理论：好玩优先

对标的是发声书/IP 点读的**情绪与节奏**，不是学段产品的效率。

| 原则 | 含义 |
|------|------|
| 点哪响哪 | 即时反馈，本地包优先 |
| 可重复好玩 | 同一角色多句随机（weight） |
| 模式切换 | 自由点读 / 听故事 / 儿歌 / 轻探索 |
| 玩具感 | 音效、彩蛋、短句，多于长课文 |
| 成就感 | 自己贴的、自己印的书更愿意反复点 |

**供给模型与 JoJo 不同：**  
JoJo = 官方套装内容；益米 = **用户与社区生产内容**，官方只给样例与工具。

## 5. 双 DIY 理论

### 5.1 路径 A · 实体万物（贴纸）

```
空白 OID 贴纸 → 贴到物体（香蕉/水杯/玩具）
    → 命名 / 拍照辅助
    → 文案或 AI 故事 + 亲情音色 TTS（或固定录音）
    → 笔点 OID → 播放
```

**理论意义：** 点读对象从「某一本书」扩展为「被贴纸标记的世界」。

### 5.2 路径 B · 图书（拍照成书）

```
拍实物/画作 → 风格化成页 → 旁白/TTS → 标准 Pack
    → 打印成实体小书 → 页码/贴纸 OID → 笔点读
```

**理论意义：** 家庭记忆与儿童创作进入可点读介质；实体与数字同一套包格式。

### 5.3 统一抽象

两条路径最终都落成：

```
Pack / book.json  ·  Hotspot(OID)  ·  Clip(音频或可合成文案)  ·  可选 VoiceProfile
```

笔与引擎**只认格式，不认内容来源品牌**——这是开放的技术前提。

### 5.4 方案 A / B（战略取舍）

| 方案 | 内容 | 理论地位 |
|------|------|----------|
| A 极致普惠 | 公版 + 自制 + 拍照/贴纸生成 | **主航道** |
| B 硬件降维 | 笔触发家居 / 大模型童话 | **增值层**，不作唯一卖点 |
| 盗版兼容 | 读大厂加密书 | **禁止** |

## 6. 亲情音色理论（你确认的重点）

### 6.1 定义

**亲情音色（Family Voice Profile）**：  
用监护人同意下采集的少量语音样本，建立可复用的「朗读音色」；之后任意新文本（手打或 AI）以该音色合成语音，供点读播放。

### 6.2 不是什么

| 概念 | 是否本产品 |
|------|------------|
| 声音复刻 / 指定说话人的 TTS | **是** |
| 固定一句 mp3 只能播原句 | 可并存，能力较弱 |
| 声纹解锁、支付核身 | **否** |
| 识别「现在是谁在用笔」 | **否**（至少非 v1 目标） |

### 6.3 两阶段模型

```
【录入 Enrollment】
  跟读 N 句 → 样本 →（特征/模型）→ VoiceProfile(status=ready)
  必备：明示同意 consent

【使用 Synthesis】
  文本 + voiceProfileId → TTS/复刻 → 音频
  → 建议缓存为文件 → 点读离线播
```

### 6.4 产品价值

- 情感：熟人声 > 通用女声  
- 规模：句子可无限变，不必每句真人录  
- 差异：家庭专属，难被标准书库复制  
- 与 DIY：贴纸/绘本旁白默认可挂「妈妈声」

### 6.5 伦理底线（理论级）

- 同意、可删、默认本地、云端二次授权  
- 儿童声音须监护人同意  
- 禁止未授权模仿他人/公众人物并公开传播  
- 公开 Pack 不得夹带他人 VoiceProfile 样本除非授权

## 7. 内容与版权理论

### 7.1 分层

| 层 | 谁拥有 | 默认去向 |
|----|--------|----------|
| 引擎/协议/工具代码 | 社区（Apache-2.0） | 公开 |
| 官方样例包 | 项目声明的许可 | 公开 |
| 家庭 DIY 绑定/录音/音色 | 用户家庭 | **默认仅本地** |
| 社区投稿 Pack | 作者 + pack.meta 许可 | 审核后公开索引 |

### 7.2 「资源广」的合法公式

```
资源广 = 工具好用 × 创作门槛低 × 合规包可发现
       ≠ 盗版库体积
```

### 7.3 AI 的角色

AI 是 **作者助手**（识物建议、故事草稿、风格化图、TTS），不是自动盗版机。  
生成物写入笔前：**家长预听/确认**；儿童安全过滤为默认档。

## 8. 系统分层理论

```
┌─────────────────────────────────────────┐
│  创作层  DIY Studio / 社区作者 / AI 助手  │
├─────────────────────────────────────────┤
│  内容层  Pack · book.json · DIY 绑定     │
│         · VoiceProfile · 音频缓存        │
├─────────────────────────────────────────┤
│  引擎层  命中(OID/坐标) · 播放策略       │
│         · 模式 free/story/song/explore   │
├─────────────────────────────────────────┤
│  设备层  笔 / 模拟器 · 协议 · 本地存储   │
├─────────────────────────────────────────┤
│  可选桥  MQTT / HA（米家友好，非官方）    │
└─────────────────────────────────────────┘
```

**依赖方向：** 上可换、下可换；**中间 Pack 格式是稳定性契约**。

### 8.1 点读管线（不变式）

```
Tap → 解析 Hotspot（书 或 DIY）
    → 按 playPolicy 选 Clip
    → 若文案型且有 VoiceProfile → 合成或读缓存
    → 播放（replace / queue / random_one）
```

### 8.2 播放策略语义

| policy | 语义 | 典型 |
|--------|------|------|
| replace | 新点打断旧播 | 自由点读默认 |
| queue | 排队连播 | 听故事旁白 |
| random_one | 多句加权随机一句 | 角色/贴纸多台词 |

## 9. 品牌与「米家」理论

| 主张 | 说明 |
|------|------|
| 名 | 益米 = 有益 + 社区「米」意象；**非小米子公司** |
| 米家友好 | 开放状态/事件，方便用户自建自动化 |
| 不主张 | 官方生态链、小爱官方技能默认集成、未授权商标 |
| IoT 定位 | 点读生活的开关（如故事结束关灯），**不是**中控主机替代品 |

对外表述模板：

> 益米点读笔为独立开源项目，支持可选的本地/MQTT 互联，**并非**小米或米家官方产品。

## 10. 能力路线图（理论优先级，非排期承诺）

### P0 理论已定、宜先实现的骨架

1. 开放 Pack / book 格式与校验  
2. 点读引擎 + 模拟器  
3. DIY OID 绑定 + 文案 clip  
4. VoiceProfile 数据模型与同意字段  
5. 社区红线与投稿规范  

### P1 体验闭环

6. 真录音样本录入  
7. 真 TTS / 复刻（可先单一云或开源方案）  
8. 合成结果缓存离线点读  
9. 家长端最小绑定 UI  

### P2 双 DIY 完整

10. 拍照标签 / 故事模板  
11. 卡通化 + 打印模板  
12. 一键导出 Pack  

### P3 生态

13. Pack Hub 与 CI  
14. MQTT/HA 桥  
15. 固件实机  

**原则：** 先本地可玩，再云；先同意与删除，再上复刻模型。

## 11. 成功标准（如何判断理论成立）

| 维度 | 信号 |
|------|------|
| 好玩 | 同一贴纸被反复点、随机句被当游戏 |
| 创作 | 家庭绑定数、自制页/包数 |
| 声音 | 使用亲情音色的比例、家长主观「像不像」 |
| 合规 | 侵权下架少、无「盗版库」叙事 |
| 开放 | 第三方包/ fork 工具出现 |

不作为早期 KPI：题库覆盖率、年级同步率、官方米家货架排名。

## 13. 延伸决策（专题定稿并入 · D11–B8）

完整条文见三份专题；此处只列拍板摘要。

### 安全（[safety.md](./safety.md)）

| ID | 决策 |
|----|------|
| D11 | 儿童优先；AI/拍照写入前家长确认门；失败可感知 |

## 16. 冻结声明

- 本文 **v0.1** + 三专题 **v0.1** 共同构成产品理论基线。  
- 改 D1–D16 / H1–H10 / B1–B8 须升版本并写变更说明。  
- 工程实现可以 stub，但**不得**做成教辅笔、盗版兼容机，或「无服务器就不能点自己的包」。  

**最终心智模型：**

> 一张贴纸让沙发上的香蕉会用妈妈的声音说话；  
> 一张照片能走进你们自己打印的小绘本；  
> 格式开放，内容自创，声音有温度，规则守得住。
