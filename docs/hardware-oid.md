## 0. 一句话

**笔是「低延迟本地发声器 + OID 读取器」；智慧在 Pack 与家庭库，不在笔上跑大模型。OID 与空白贴纸是万物可点的物理锚点，必须有码段治理与失败体验，不能只写一个字符串。**

---

## 1. 硬件角色假设（产品架构）

```
┌──────────── 笔（Device）────────────┐
│  OID/光学头 → 解码 → oid 字符串      │
│  本地音频解码播放                     │
│  本地/卡存储：Pack + DIY 缓存         │
│  按键：音量/暂停；灯语；电池           │
│  连接：USB / BLE（装包、同步、可选桥） │
└────────────────────────────────────┘
         │ protocol
         ▼
┌──────── 手机/电脑（可选）────────────┐
│  DIY 绑定、音色录入、AI 助手、装包    │
└────────────────────────────────────┘
```

| 原则 | 说明 |
|------|------|
| **H1 点读本地** | 已装内容点读不依赖云 |
| **H2 笔不做重 AI** | 复刻 TTS/识图在手机或家庭网关；笔收成品音频 |
| **H3 无屏可玩** | 主路径可无屏；灯+音足够表达状态 |
| **H4 模拟器等价** | `device-sim` 先验证逻辑；实机只换传输与解码 |

## 2. OID 与识别理论

### 2.1 什么是益米语境下的 OID

**逻辑 OID：** 引擎与 DIY 使用的唯一字符串 ID（如 `YIMI-DIY-BANANA`）。  
**物理码：** 印在贴纸/书页上的光学图案，笔读出后映射为逻辑 OID。

```
物理图案 --decode--> 逻辑 OID --resolve--> Hotspot/DIY → Clip
```

### 2.2 方案中立（不锁死供应商）

理论层只约束：

| 要求 | 说明 |
|------|------|
| 稳定可读 | 目标年龄正常点按成功率（量产定指标，如 ≥95%@标准距离） |
| 可量产印刷 | 贴纸与书刊印刷可行 |
| 可分配码空间 | 足够 DIY + 书包 + 厂测 |
| 授权可承受 | 社区硬件路线须披露授权模式；拒绝「只许一家闭源、社区永不可复制」的唯一绑定作为**唯一**官方方案 |
| 开源友好度 | 优先文档可公开的协议；若必须闭源解码库，则隔离为可选驱动层 |

**候选技术族（调研用，非定标）：** 传统 OID 点码、超声波/点阵纸变体、特定芯片方案商码图等。  
**定标程序：** 先从公开零售渠道单买两套同板号/revision 的近期一体主板与配套真实 OID 光头，以同一板号、固件和机械/声学边界做成 EVT-0；通过整机门后，再用同一 `BOM-REV-A` 做批量 RFQ、授权和第二来源评估。只有当前一体主板全部失格时，才单买真实 OID 模组并进入同版自研主板分支。样机不使用临时视觉码或开发板架构替代目标方案。

### 2.3 逻辑码空间治理

| 段 | 用途 | 例 |
|----|------|-----|
| `YIMI-SYS-*` | 系统保留（校准、帮助） | |
| `YIMI-BOOK-*` / 包内自管 | 正式书包热点 | 书内可自有命名，安装时登记 |
| `YIMI-DIY-*` | 用户空白贴/用户分配 | `YIMI-DIY-0A31` |
| `YIMI-TEST-*` | 厂测与开发 | |

**规则：**

- 逻辑 OID **全局唯一**于「家庭库 + 笔内已装包」；社区 Pack 冲突时安装器提示覆盖/改名映射。  
- 空白贴纸出厂可预烧/预印 **大随机码**，App 绑定只改语义不改码。  
- 可选：社区 **码段注册表**（防两家开源硬件撞码）——Gen1 可先家庭内唯一，Gen2 再全球注册。

### 2.4 无 OID 路径（降级，非 Gen1 必做）

| 模式 | 态度 |
|------|------|
| 页坐标点读 | 需摄像头/定位，复杂度高 → **P2+** |
| 纯 App 点图 | 可做编辑预览，**不替代笔** |
| 二维码 | 可作调试，幼儿点读体验差，不作主路径 |

## 3. 贴纸体系

### 3.1 SKU 分档（与 safety 一致）

| SKU | 用途 | 材料 |
|-----|------|------|
| **物面贴** | 杯、书、木、塑 | 常规文具/玩具材料合规 |
| **食品接触贴**（可选） | 临时演示果蔬 | 单独认证与标识 |
| **书页贴/印刷码** | 绘本 DIY 页角 | 印刷套准友好 |
| **透明覆膜码** | 不挡插画 | 工艺项 |

### 3.2 空白贴生命周期

```
生产印码 → 质检抽读 → 包装
  → 用户贴到物体 → App 绑定语义
  → 使用 → 磨损/撕毁 → 可换新贴（同语义迁到新 OID 或支持「迁移绑定」）
```

**迁移绑定（理论要有）：**  
旧 OID 内容一键转到新 OID，旧码作废——解决「贴纸烂了」。

### 3.3 防伪与垃圾码

- 开源项目不靠加密防伪赚钱；可对**官方空白贴**做轻量校验（可选）。  
- 用户打印自造码：自担识别率；工具提供「可印码生成器」时声明非儿童安全材料保证。

## 4. 笔侧能力清单（Gen1 最小）

### 必须（MVP 硬件）

| 能力 | 说明 |
|------|------|
| 读码 | 输出逻辑 OID |
| 播放 | 本地解码常见格式（如 mp3/wav 之一） |
| 存储 | 预装 + 用户包 + DIY 缓存，容量档位可分 SKU |
| 音量键 | 硬件键优先 |
| 电量 | 可提示低电 |
| 装包通道 | USB 至少一种；BLE 可选 |

### 应有

| 能力 | 说明 |
|------|------|
| 灯语 | 开机/连上/失败/播放 |
| 暂停 | 键或再点策略 |
| 配对 | 家庭设备白名单（安全） |

### 明确可不做（Gen1）

| 不做 | 原因 |
|------|------|
| 笔内大模型 | 成本、延迟、电池 |
| 笔内录音录入爸妈音色 | 录入在手机；笔只播 |
| 彩色屏 | 成本与儿童摔打 |
| 官方小爱芯片绑定 | 品牌与认证边界 |

## 5. 延迟预算（理论指标）

**目标：点到首音 &lt; 200ms（本地已缓存音频时）。**

| 阶段 | 预算量级 |
|------|----------|
| 光学读码+解码 | ~30–80ms |
| 查表 resolve | &lt;5ms |
| 音频启动 | ~20–50ms |
| 余量 | 机械按压、文件系统 |

**超时：**  
若需现合成 TTS（未缓存）：允许先播短「嗯」提示，再播正文；或强制「仅缓存可点」。  
**理论默认：写入笔的必须是可离线 Clip 文件，禁止「点一下现场等云 2 秒」。**

## 6. 存储与装包

### 6.1 存储分区（逻辑）

```
/system     固件与系统音
/packs      已装主题包
/diy        绑定索引 + 用户音频缓存
/voices     可选：音色相关缓存（非原始样本也可只在手机）
/tmp        传输暂存
```

### 6.2 满容量策略

1. 提示清理最少用包  
2. 优先删 TTS 缓存（可重建）  
3. 不静默删用户录音原件（需确认）

### 6.3 装包信任

| 层级 | 说明 |
|------|------|
| 格式校验 | book.json / pack.meta schema |
| 完整性 | checksum |
| 来源 | 家庭自签 / 社区签名可选 |
| 配对 | 仅已配对手机可灌（防校园乱灌） |

协议细节可演进；原则是 **最小可信装包**（safety D 与本专题共同要求）。

## 7. 打印绘本套准（双 DIY 路径 B）

| 问题 | 策略 |
|------|------|
| 家用打印缩放 | 模板固定 mm 尺寸；导出 PDF「实际大小」警告 |
| 码与图错位 | 页角码在出血外安全区；提供套准框 |
| 低墨识别差 | 提示检测页：印测试码用笔点检 |
| 装订裁切 | 安全边距规范写入 pack 打印指南 |

Gen1 可先推 **单页卡 + 手贴空白 OID**，降低套准难度；整本印刷码为 Gen2。

## 11. 决策摘要

| ID | 决策 |
|----|------|
| H1–H4 | 本地点读；笔不做重 AI；无屏可玩；模拟器等价 |
| H5 | 逻辑 OID 与物理码分离；码段治理 |
| H6 | 方案中立 + 评测定标；解码可隔离 |
| H7 | 贴纸分档；支持绑定迁移 |
| H8 | 点读首音 &lt;200ms；入笔须可离线 |
| H9 | 装包校验 + 家庭配对 |
| H10 | 打印套准规范；Gen1 可手贴码降复杂度 |
| H11 | EVT-0 与目标产品同物理码、同架构、同 BOM/固件和同质量门；单件阶段只改变采购数量与生产组织 |

没有可信的码与笔，双 DIY 只是 App 幻想；没有开放格式，笔只是又一个封闭玩具。两者缺一不可。
